# cc-web 总方案

## 一句话

起一个本地服务器，把 headless Claude Code 子进程当引擎，在浏览器里
接着聊当前会话。**不改 CC 本体**（改不了，是分发的原生二进制）。

## 目标

1. 浏览器里能看到并继续 TUI 里正在进行的会话。
2. 能发提示词、看流式输出、中断。
3. 能切模型、切权限模式。
4. **工具审批弹在浏览器里**——没这条就只能开 bypass 裸奔，等于玩具。
5. 看得到用量：会话成本 + 订阅额度（5 小时 / 7 天窗口）。
6. 全程本地，断网可用。

## 非目标（明确不做）

- **不做云端**。要跨设备用 `/remote-control`，那个免费且已经很好。
- **不重写 agent loop**。引擎永远是 CC 本体，我们只做桥接。
- **不做多用户**。单机单人，绑 `127.0.0.1`。
- **第一阶段不做好看的 UI**。UI 是占位的，等功能测完再换组件——
  这个约束反过来决定了架构（见 ARCHITECTURE D2）。

## UI 先用通用的会话式布局

第一阶段 UI 只要能验证功能，信息结构用通用的三段式：
左边会话列表 / 中间对话流 / 右边（或顶部）状态区（模型、权限模式、用量）。
组件用最朴素的实现，**不引入组件库**——引入了之后换起来更麻烦。

关键约束写在 D2：**UI 层不写测试**。任何值得测的逻辑都必须下沉到 server。
这样以后整个 `src/web/` 删掉重写，测试一条都不用改。

## 里程碑

按 TDD 顺序排，每个里程碑都是「先红后绿」，做完能独立验证。
详细测试清单见 `docs/TDD.md`。

| # | 里程碑 | 产出 | 卡点风险 |
| --- | --- | --- | --- |
| M0 | 测试基础设施 | 假 `claude` 二进制 + vitest 跑得起来 | 低 |
| M1 | 引擎层 | spawn / NDJSON 解析 / 事件流 / 生命周期 | 中：孤儿进程 |
| M2 | 会话读取 | 解析 `~/.claude/projects/**/*.jsonl`、聚合 usage | 低 |
| M3 | HTTP 只读 | `/meta` `/sessions` `/sessions/:id/history` | 低 |
| M4 | WebSocket | 事件流推到浏览器 | 中：多标签页、断线补发 |
| M5 | 发提示词 + 中断 | 双向通了 | 中 |
| M6 | 控制协议 | `set_model` / `list_models` / `set_permission_mode` | 中：类型有了，运行时要探测 |
| M7 | 工具审批 | `can_use_tool` 反向请求 | **高：超时会卡死引擎** |
| M8 | 鉴权 | token + `#fragment` | 低 |
| M9 | 用量 | `get_usage`：会话成本 + 订阅额度 | 低：有官方通道 |
| M10 | 交接入口 | `SessionEnd` hook + CLI | 中 |
| M11 | 占位 UI | 能用就行 | 低 |

**M7（工具审批）是唯一真正的风险点**，其它都是常规工程——
因为 SDK 的 `.d.ts` 里有全部控制协议的类型定义（见 PROTOCOL §0），
不用猜。但类型不等于运行时，建议 M1 做完立刻跑一次契约探测
（`docs/TDD.md` 的 probe 流程），把实际帧录下来。

M7 难在三件事叠一起：超时（不做就永久卡死引擎）、去重
（同一 requestId 会到达两次）、取消（对方可能撤回）。
三条都写在 `docs/RISKS.md` R2 / R5。

## 交付顺序建议

M0 → M1 → **先跑 probe** → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9 → M10 → M11

M8（鉴权）排这么后是因为开发期绑 `127.0.0.1` 本来就进不来；
但**上线前必须做完**，这个服务器能读写文件和跑 shell。
